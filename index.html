02 — Featured project

GT Movies Store

A full-stack movie storefront built with Django, connecting a browsable catalog to accounts, cart management, and a purchase flow.

01

The challenge

Make an end-to-end store feel simple.

The project brings multiple systems together behind one coherent journey. A user can discover a title, learn more, create an account, build a cart, understand the total, and complete the flow without losing context.

Screens & features

One journey, four key moments.

Each screen answers a specific user need and hands the user naturally to the next step.

01

Movie catalog

Browse & discover

The home and catalog views organize the collection into a clear grid, helping visitors scan titles and move quickly from discovery to decision.

“As a visitor, I want to browse available movies so I can find something I want to purchase.”
02

Movie details

Understand the title

Individual movie pages surface the title, image, description, price, and action controls together so the user has enough context before adding an item.

“As a shopper, I want to view a movie’s details so I can make an informed choice.”
03

Cart & purchase

Review the order

The cart keeps selected movies, pricing, and the order total in one place. Users can remove items, clear the cart, or continue to purchase.

“As a shopper, I want to manage my cart and see the total before completing my purchase.”
04

Account access

Continue securely

Sign-up and sign-in flows connect purchases to an authenticated user while keeping browsing open and the path to checkout understandable.

“As a returning user, I want to sign in so I can access the protected parts of the store.”

User-story coverage

Requirements translated into working behavior.

  • Browse a catalog of available movies
  • Open a movie to view its full details
  • Create an account and sign in
  • Add selected titles to a shopping cart
  • Review the total and remove unwanted items
  • Complete the purchase flow
03 — Process & methodology

Build, test, learn,
then build again.

I followed an iterative, user-story-driven approach: turn one requirement into a small working slice, test it, resolve what I learned, and then move forward.

01

Define

Translate stories into flows

I began with the required user stories and mapped each one to a screen, a route, and a clear user action. This kept the work centered on what the user needed to accomplish.

02

Build

Develop in small slices

I built the Django application feature by feature—models and routes first, then templates, styling, accounts, and cart behavior. Each slice was tested before adding the next.

03

Debug

Follow the error trail

When questions came up, I reproduced the issue, read the Django error message and traceback, checked the relevant URL, view, or template, and changed one thing at a time.

04

Ship

Version and deploy

I used Git and GitHub to preserve progress, then configured the app for PythonAnywhere. Deployment became a final test of paths, settings, static files, and the full user journey.

How I navigated questions: documentation first, error messages second, focused searches when needed, and small experiments to confirm the cause before changing more code.
